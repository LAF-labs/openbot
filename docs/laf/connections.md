# 외부 앱 연결 — 결정 기록 (2026-08-30)

노션·MS 오피스·GTM 같은 일상 도구를 봇에 연결해 달라는 요구에 대한 답과,
그 답이 이 모양이 된 이유.

## 측정이 결정했다

벤더 공식 원격 MCP 서버 일곱 곳(Notion, Atlassian, Slack, Box, Canva,
Linear, Stripe)을 무인증으로 찔러 본 결과 **전부 OAuth 전용**이었다 — 일곱
번 모두 401에 RFC 9728 `resource_metadata`가 붙어 돌아왔다. 우리 클라이언트는
정적 Bearer 토큰만 보낼 수 있었으므로, **카탈로그에 있던 다섯 벤더(Atlassian,
Box, Slack, Salesforce, ServiceNow)조차 실제로는 연결이 성립한 적이 없는
장식이었다.** 없는 것을 다섯 개 진열하는 화면은 제품이 감당할 수 없는 주장을
하므로, 업스트림의 같은 판단을 따라 다섯 엔트리를 제거했다. 히스토리에 있고,
되살리는 일은 그 벤더의 OAuth 엔드포인트를 고정하는 리뷰다 — 리버트가 아니라.

## 구현은 업스트림에서 가져왔다

직접 쓰지 않고 업스트림(CopilotKit/openbot)의 사람별 OAuth 커넥터 작업을
이식했다 — `#242`(a6bada9)의 노션 커넥터와 그 위의 보안 후속 커밋들이 원본이고,
`oauth.ts`(봉인 상태·PKCE·동적 등록), `transport.ts`, `google-drive-rest.ts`,
credentials 금고의 회전 직렬화, 스키마(`mcp_user_credentials`,
`credentials_active_key_idx`)가 거의 그대로 왔다. 체리픽이 아닌 이식인 이유:
업스트림의 커밋은 채널 기능과 뒤섞여 있고, 그들의 store는 #21 이후
멀티프로세스로 재편된 기반 위에 있다.

**지킨 것**: 이 포크의 경계 기계는 그대로다. ask/승인 흐름, 커스텀 서버의
LAF 계약(어노테이션 신뢰 + 정의 해시 동의 고정, docs/laf/mcp-contract.md),
`settleWithoutAsking` — 전부 이식 전과 동일하게 모든 호출을 판정한다.
업스트림에서 가져온 것은 자격 증명이 오가는 기계이지, 무엇이 허락되는지를
정하는 기계가 아니다.

**단일 프로세스에서도 잠금은 남겼다**: 리프레시 토큰을 회전시키는 벤더(노션이
그렇다)는 방금 보여준 토큰을 즉시 죽이므로, 동시 호출 두 개가 같은 토큰을
제시하면 재사용 감지가 그랜트 전체를 폐기한다. 프로세스 내 직렬화(맵)와 행
잠금(FOR UPDATE)은 그 경쟁 자체에 대한 답이라 배포 모델과 무관하게 필요하다.

## 사람별 연결이라는 모양

연결은 배포가 아니라 **사람**의 것이다. 배포는 OAuth 클라이언트(벤더에게
자신을 소개하는 신분)만 갖고, 각 사람이 자기 계정으로 동의하며, 호출은 그
사람의 그랜트로 나간다. 같은 질문을 두 사람이 던지면 각자 자기 계정이 볼 수
있는 답을 받는다 — 대체 경로(fallback)는 일부러 없다.

## 벤더별 현황

| 서비스 | 상태 | 방법 |
|---|---|---|
| Notion | ✅ 카탈로그 | 호스티드 MCP + 동적 등록(RFC 7591). 콘솔 작업 0 — 라이브로 검증: 실제 등록 엔드포인트가 공개 클라이언트를 발급했고 동의 URL이 302로 진입함 |
| Google Drive | ✅ 카탈로그 (읽기 전용) | GA REST 어댑터(공식 MCP는 프리뷰 게이트). 운영자가 Google Cloud Console에 클라이언트를 등록해 붙여넣어야 함 — 아래 함대 절 참조 |
| MS 오피스 | 봇 브라우저 | 공식 원격 MCP 없음. office.com에 봇 브라우저로 로그인 — 이미 동작하는 경로 |
| GTM(구글 태그 매니저) | 봇 브라우저 | 공식 원격 MCP 없음. 콘솔에 로그인해 쓰게 한다 |
| Atlassian·Slack 등 | 히스토리 | OAuth 엔드포인트 고정 리뷰를 거쳐 엔트리로 복귀 가능 |

카탈로그 밖 서비스의 일반 답은 두 가지다: 웹 UI가 있으면 봇 브라우저(로그인
한 번), 고객사가 자기 시스템을 붙이려면 LAF MCP 계약(mcp-contract.md)의
커스텀 서버.

## 함대 운영 메모

- **새 환경 변수 없음.** 콜백 origin은 `BETTER_AUTH_URL`에서 유도된다 —
  로그인되는 배포는 이미 그 값을 선언하고 있고, caddy의 `handle /api/*`가
  콜백을 서버로 넘긴다. 노션 연결은 배포 직후 바로 눌러서 된다.
- **Google Drive는 운영 작업이다.** 구글은 동적 등록이 없고,
  `drive.readonly`는 restricted scope라 프로덕션 승인(보안 심사)이 필요하다.
  VM마다 도메인이 다르므로 클라이언트 하나에 고객 콜백 URI를 계속 추가하는
  모양이 되는데, 그건 한 콘솔 목록에 고객 도메인이 쌓인다는 뜻이기도 하다.
  A3(카카오·네이버·구글 로그인 콘솔)과 같은 부류의 후속 결정으로 남긴다 —
  코드는 준비되어 있고, 화면은 등록할 redirect URI를 그대로 보여준다.
- **데스크톱 셸에서의 동의 화면**: 셸(웹뷰) 안에서 벤더 동의 페이지로
  넘어가는데, 그 페이지 안의 구글 SSO는 웹뷰를 거부할 수 있다
  (`disallowed_useragent`). 그때의 우회는 링크를 시스템 브라우저로 여는 것 —
  콜백은 세션이 아니라 **봉인 상태**에서 신원을 읽으므로, 다른 브라우저에서
  동의를 마쳐도 연결은 정확히 그 사람에게 붙는다. 셸이 `_blank`를 시스템
  브라우저로 넘기게 하는 다듬기는 후속.
- **감사 트레일이 늘었다**: `mcp.oauth_client_registered`,
  `mcp.account_connected/disconnected`(사유 3종 구분), `mcp.call_failed`
  (허용됐으나 실패한 호출 — 이전엔 성공으로 적혔다), `reachedAs`(누구의
  자격으로 나갔는지).
