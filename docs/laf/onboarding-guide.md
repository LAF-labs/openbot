# 연결 가이드 — 자사 서비스를 LAF 봇에 붙이기

계약은 [mcp-contract.md](mcp-contract.md) 한 장이 전부다. 이 문서는 순서다.

## 권장 규모

- **툴 10개 이하.** 봇이 실제로 쓰는 것은 좁고 깊은 몇 개다. 200개짜리
  API 미러는 모델의 컨텍스트만 태운다.
- `laf.watch`의 신호는 "이게 멈추면 큰일"인 것들만. 텔레메트리가 아니라
  당직 목록이다.

## 순서

1. **템플릿 복사** — `examples/watch-server-template/` 를 자사 레포로.
   `collectSignals()` 하나만 채우면 `laf.watch`가 완성된다.
2. **자유 툴 추가** — 봇에게 시킬 일 단위로. 툴마다 어노테이션을 선언한다
   (계약 §2). 쓰기 툴은 처음부터 만들지 말고, 읽기만으로 한 주 굴려본 뒤
   필요해진 것만 추가하는 쪽이 실제로 빠르다.
3. **검사** — `bun server/scripts/laf-mcp-check.ts <url>` 통과까지 수정.
4. **배포** — 자사 인프라에. 코드 리뷰·비밀 관리·가용성은 자사 책임이다.
   플랫폼에는 URL과 Bearer 토큰만 전달된다.
5. **등록** — LAF 관리 화면(`/api/watch/sources`, kind=mcp)에 URL 등록.
   봇별로 어떤 툴을 줄지(grant)와 폴링 주기를 정한다.

## 등록되면 일어나는 일

- 플랫폼이 `laf.watch`를 주기 폴링한다 — **모델 없이, 순수 코드로.**
  신호의 출현·소멸·전이만 이벤트가 된다.
- 변화가 있고 담당 봇이 지정돼 있으면 그 봇이 깨어나 변화 보고를 받는다.
- 매일 아침 다이제스트 한 장: 지금 막혀 있는 것, 밤사이 전이, 런 통계.
- 자유 툴은 봇 대화에서 위험도 선언대로 실행된다 — 읽기는 조용히,
  파괴적·발신·돈은 사람 승인을 기다린다.

## 하지 말 것

- 문턱 판정을 플랫폼에 미루는 것 — status는 서버에서 확정해 내보낸다.
- 백엔드 장애를 프로토콜 에러로 내는 것 — 신호로 답한다(계약 §1.2).
- 어노테이션 생략 — 전부 destructive 취급되어 봇이 사실상 못 쓴다.
- 등록 후 어노테이션 하향 — 자동 정지 + 재동의가 걸린다.
