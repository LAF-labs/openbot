# 연결 가이드 — 자사 서비스를 LAF 봇에 붙이기

계약은 [mcp-contract.md](mcp-contract.md) 한 장이 전부다. 이 문서는 순서다.

## 권장 규모

- **툴 10개 이하.** 봇이 실제로 쓰는 것은 좁고 깊은 몇 개다. 200개짜리
  API 미러는 모델의 컨텍스트만 태운다.
- `laf.watch`의 신호는 "이게 멈추면 큰일"인 것들만. 텔레메트리가 아니라
  당직 목록이다.

## 순서

1. **템플릿에서 시작** — [LAF-labs/laf-mcp-template](https://github.com/LAF-labs/laf-mcp-template)의
   **Use this template**로 자사 레포를 만든다. `collectSignals()` 하나만
   채우면 `laf.watch`가 완성되고, 검사기와 CI가 같이 따라온다.
2. **자유 툴 추가** — 봇에게 시킬 일 단위로. 툴마다 어노테이션을 선언한다
   (계약 §2). 쓰기 툴은 처음부터 만들지 말고, 읽기만으로 한 주 굴려본 뒤
   필요해진 것만 추가하는 쪽이 실제로 빠르다.
3. **검사** — `bun run check`(템플릿 동봉) 통과까지 수정. 템플릿의 CI가
   매 푸시마다 같은 검사를 돌린다.
4. **배포** — 자사 인프라에. 코드 리뷰·비밀 관리·가용성은 자사 책임이다.
   플랫폼에는 URL과 Bearer 토큰만 전달된다.
5. **등록** — LAF 관리 화면의 플러그인(MCP 서버)에 URL과 Bearer 토큰을 등록하고,
   봇별로 어떤 툴을 줄지(grant) 정한다.

## 등록되면 일어나는 일

- 자유 툴은 봇 대화에서 위험도 선언대로 실행된다 — 읽기는 조용히,
  파괴적·발신·돈은 사람 승인을 기다린다. 이것이 지금 도는 부분이다.
- `laf.watch`는 **계약으로 남아 있고, 플랫폼의 주기 폴링은 보류다.**
  템플릿·검사기(`bun run check`)·계약 §1은 그대로이고, 그것을 채운 서버는
  지금 등록해도 자유 툴로 완전히 동작한다. 폴링과 아침 다이제스트를 돌리던
  코드는 삭제됐다 — 화면이 없었고 봇을 깨우는 호출이 인증을 통과하지 못했다
  (`docs/laf/redesign-2026-09.md` §7-2). 첫 요구 고객이 생기면 git에서 되살린다.
- 그때까지 `laf.watch`를 미리 채워 두는 값은 그대로다: 되살아나는 날 손댈
  것이 없고, 그 사이에도 봇이 툴로 직접 불러 상태를 물어볼 수 있다.

## 하지 말 것

- 문턱 판정을 플랫폼에 미루는 것 — status는 서버에서 확정해 내보낸다.
- 백엔드 장애를 프로토콜 에러로 내는 것 — 신호로 답한다(계약 §1.2).
- 어노테이션 생략 — 전부 destructive 취급되어 봇이 사실상 못 쓴다.
- 등록 후 어노테이션 하향 — 자동 정지 + 재동의가 걸린다.
